# 界面文案规范

界面先回答三个问题：这里能做什么、点击后会发生什么、下一步该做什么。以用户的阅读和学习任务命名入口，以具体动作命名按钮。

## 写法

- 一个功能只用一个名称。按钮、页签、标题、提示、可访问名称和使用说明同步更新。
- 保留《学习观》的专有名词和领域术语，包括判别模型、联结模型、渐构靶图、内涵、陪域、判别上料/下料、联结上料/下料和下上对照。可以在旁边解释含义，不能用通俗别名替换概念名称；槽位与变量也不混称。
- 按钮用“动作＋对象”，如“生成知识图”“删除书签”。页签和分组使用同一层级的任务名称。
- 把结果和下一步放在提示开头。错误说明包含补救动作；进度只描述当前任务，不承诺固定完成时间。
- 帮助文字先说用户需要理解的影响。API、存储和部署细节留在开发文档；格式、单位、版本和来源影响用户选择时保留。
- 用简短标题帮助扫读，详细限制放在相关操作旁。删除说明指出对象和范围，保存说明区分草稿、个人记录与正式知识图。
- 名称和语法的重复形成一致性；同级标题保持并列；提示紧邻相关操作；用明确的动词区分阅读、生成、核对和修改。
- 原文可定位、原文支持、外部事实核查是三种状态。AI 建议、用户自述和练习自评必须明确标注，不写成已验证或已掌握。

这些写法参考 [Steve Krug 的《Don't Make Me Think》](https://sensible.com/dont-make-me-think/)及其[官方样章](https://ptgmedia.pearsoncmg.com/images/9780321965516/samplepages/0321965515.pdf)中关于扫读、清楚导航和删减冗余文字的原则；将 Robin Williams 的《写给大家看的设计书》中对比、重复、对齐和亲密性的原则用于文案层级与分组，见[出版方介绍](https://www.informit.com/store/non-designers-design-book-9780133966152)。这是界面措辞的应用，不改变两本书的原意，也不把文案调整当作视觉布局改版。

## 统一名称

| 原名称 | 界面名称 | 含义 |
| --- | --- | --- |
| 图文阅读 | 阅读知识图 | 查看知识图并定位原文 |
| 检索与学习 | 查找与学习 | 查找知识、问答、练习和跨书对照 |
| 审校处理 | 检查与修正 | 检查问题、复核结论和确认修改 |
| 资料 / 输入资料 | 导入资料 | 输入正文或上传文件 |
| AI 拆分 / 拆成知识图 | 生成知识图 | 从资料生成新的知识图 |
| 追加拆分 | 追加资料 | 为当前知识图补充资料 |
| 重新开始 | 新建知识图 | 建立新的资料工作区 |
| 阅读地图 | 阅读导航 | 从章节和概念线索进入原文 |
| 任务视图 | 阅读书签 | 保存当前资料的浏览位置和筛选 |
| 联结模型 | 联结模型（保留术语） | 查看输入、输出、规律和适用条件 |
| 渐构靶图 | 渐构靶图（保留术语） | 独立记录自己的内涵表述、规律和例子 |
| 下上对照 | 下上对照（保留术语） | 对照具体实例和对应规律 |
| 学习模式 | 学习练习 | 根据已有知识图做练习和自评 |
| 来源身份 / 内容身份 | 来源类型 / 内容性质 | 保留字段含义，减少实现术语 |
| 槽位 / 内涵 / 陪域 | 槽位 / 内涵 / 陪域（保留术语） | 保留概念及身份含义；陪域区别于已观察结果的值域 |
| 快速体检 | 规则检查 | 使用本地规则检查当前显示范围 |
| AI 深度审校 | AI 原文核对 | 用模型核对知识图与原文 |
| 增量审校 | 核对变化部分 | 按计划复用合适的历史结果 |
| 二次核实 | 复核问题 | 再次判断已有问题是否成立 |
| 可回链 | 可定位原文 | 可打开对应来源，不等于外部证实 |
| 语义已验证 | 原文支持已核对 | 记录与原文的支持关系，保留核对来源 |
| 适合画布 / 聚拢相关 | 显示全部 / 查看相关节点 | 描述点击后的可见结果 |

“联结模型”对应《学习观》的 `connection_model`，界面和本体使用同一专有名称。渐构靶图、判别/联结材料及上下层坐标也沿用原书术语。原书名称、本体标签、模型提示词、用户原文和服务返回的诊断按其来源保留，避免改变概念含义。

联结模型详情的「阅读」组包含下上对照、模型比较；「学习」组包含我的理解、情境预测、两步推测、学习记录；「核对」组包含待补充内容、核对方向、核对结构。「原文依据」是各组共用的独立阅读栏，打开或收起它不切换当前任务。条件、映射、边界各自紧邻来源提示，未定角色单独展示。面板宽度不足时原文上下排列，输入输出区域按剩余内容宽度重排。

切出联结模型工作区时，子面板暂停读取并取消尚未完成的读取，不接收迟到结果或聚焦隐藏控件；返回时重新读取当前任务。所选任务和未保存的私人草稿保留，结构写入仍需当前版本的预览和明确确认。

目录和详情在工作区首次打开时读取，隐藏期间取消未完成的读取并延后新的读取。返回时只补齐未完成或失败的目录、详情；同一文档、版本和筛选范围内已读取的内容保持挂载，避免丢失内存中的私人草稿。版本、模型、分页、筛选变化或主动重新读取仍会使对应内容失效；成功响应不写入浏览状态缓存。隐藏不会撤销用户已明确发起的方向预览或保存。

方向预览或确认保存尚未返回时，连续触发只受理一次，避免重复排队产生误导性的版本失败。请求失败保留已选角色并允许重试；确认保存失败后仍须重新预览再明确确认，服务端版本校验始终生效。

方向草稿保留开始修改时的图谱版本、端点身份和映射引文。外部版本更新后单独展示旧选择及旧引文，当前控件显示新版角色；旧草稿不能直接预览或保存到新版。用户明确放弃旧版方向修改后，才可按当前内容重新核对。旧引文不使用旧段落编号跳转当前原文，已移除的端点也保留在旧草稿提示中。

条件、映射和边界的「旁侧核对」在原文栏展示所选字段记录的完整引文、备注、分支身份及来源状态，保留当前任务。「在知识图与原文中定位」才切换阅读视图；重复引文无法唯一定位时仍须明确提示，不把旁侧展示当作已匹配或已核验。切换模型、版本或重读后不沿用旧字段引用。

联结模型查找栏使用持续可见的字段标签和当前筛选摘要。关键词、章节、待核对、概念及作用可分别清除，也可一次清除全部；概念筛选保留节点身份，清除概念时同时清除依赖它的作用。清除只更新目录并返回第一页，保留正在阅读的模型、当前任务、原文栏及未保存的修改；键盘焦点返回搜索框。搜索覆盖已记录的模型、概念、条件、映射和边界文字，命中不代表适用性验证。输入尚在等待更新时不把旧计数或旧空结果当作新结果。

章节选项来自整份资料，同一文档版本重新筛选时保留名称；版本变化或主动重读后重新获取，不把章节元数据写入浏览状态缓存。零结果区分「没有匹配的联结模型」「当前页没有模型」「这份资料尚无联结模型」，分别提供减少筛选、返回第一页或继续阅读的下一步；读取失败继续显示错误。

这轮查找交互参考 [Linear 2026 年 3 月界面更新](https://linear.app/changelog/2026-03-12-ui-refresh)的一致层级，以及 Carbon 的[筛选](https://www.carbondesignsystem.com/building-blocks/core/patterns/filtering)和[空状态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)规范。主辅阅读布局另与 [Material 的标准布局](https://m3.material.io/foundations/layout/canonical-examples/overview)对照。来源是产品设计实践，不能代替本项目的可用性测试或证明任务完成率提升。

联结模型所在浮窗跟随当前可用窗口大小收拢，四边和关闭按钮保持可达；目录、正文和原文依据按各自容器宽度重排。临时缩窄不覆盖用户保存的尺寸，恢复宽屏时还原布局；只有主动拖动或调整大小才保存位置。窗口变化不重建正文，不清除当前模型、任务、原文依据或未提交编辑。验收同时检查浮窗相对浏览器的边界，不能只看内容内部是否横向溢出。

这项适配延续 [Linear 2026 年界面设计说明](https://linear.app/now/behind-the-latest-design-refresh)的正文优先和稳定导航原则，并参考 [Material 3 列表—详情布局](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail)按可用空间安排主辅内容的做法；本项目使用 Web 容器查询和浮窗几何适配，不引入 Android 组件。

目录当前选中行提供「阅读当前模型」入口，主动将阅读位置和键盘焦点移到详情；详情提供「返回模型目录」，回到当前页的选中行。当前模型不在本页时返回搜索框，不自动清除筛选或更换分页。仅选择模型和异步读取不会主动移动焦点；这两个往返操作不重建详情，不改变当前任务、原文栏或未保存草稿。

## 检查范围

本轮核对了主菜单和四个工作区、生成与追加表单、历史和恢复任务、图布局和搜索、大图分页、节点和关系详情、阅读导航和书签、证据问答与概念档案、联结模型及结构编辑、比较和两步推测、学习练习及结果记录、渐构靶图及草稿备份、规则检查与 AI 核对、批量处理和修复、外部事实核查、原图和转写、会话知识图，以及 Chrome 扩展入口、弹窗和连接设置。

已有清楚的“保存”“取消”“关闭”等动作保留。修改界面名称后，更新现有交互回归中的定位和文字断言；保留版本冲突、取消、并发、来源限制、草稿保护和写入确认的断言。构建客户端及共享查看器，并使用原签名身份生成扩展包后运行完整检查。
